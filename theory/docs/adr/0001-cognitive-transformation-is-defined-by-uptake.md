# A transformation is cognitive when a taker takes its output up and transforms it

The vault defined a cognitive transformation as one "whose functional role *can* bear on the larger system's ability to discriminate, select, predict, …", and a mechanism as whatever performs one. The modal "can" excludes nothing, presupposes the larger system it is meant to explain, and cannot be written as a Horn clause. The Core instead defines a cognitive transformation by an existential over takers: something takes the output up and transforms it in turn (`cognitive_when_taken_up_and_transformed`). A mechanism is whatever performs one and needs no system to belong to (`mechanism_when_it_transforms_cognitively`); serving as a mechanism *in* a system is the separate, boundary-relative role (`mechanism_when_its_output_is_consumed`), and the taker inside the boundary must transform too, so that "organised cognitive system" coincides with "transforms something as a system". Decided at the rendering gate of issue #2 (PR #10).

## Considered options

- Intrinsic definition: a cognitive transformation is a local event (representation in, representation out), and uptake is a separate "integration" predicate. Rejected: to exclude a mechanical copy the intrinsic criterion needs a mental predicate on the component ("thinks", "handles meaning"), which reintroduces the small intelligence the theory refuses to build on.
- Legible form: cognitive when the output is in a form another mechanism could receive (the vault's coupling-surface sentence). Rejected: "legible" would be a fact the phenomenon author declares, so the theory could refuse nothing the author calls legible; and a mechanically typed but readable file would count.
- Uptake without requiring the taker to transform. Rejected: a logger that records everything would make every transformation cognitive. The taker must transform (a holder that only records is a coupling surface, `shared_state_when_stored_and_consumed`).
- Uptake as chosen.

## Objections accepted with the decision

- The last transformation before action has no taker inside the system. Answered by drawing the boundary to include the environment as a taker (phenomenon `action_taken_up_by_the_world`); the vault's `effective cognition = f(…, environment)` supports it.
- A transformation nobody has read yet is not cognitive until it is taken up, and the status can change later. Accepted: uptake has no date (`paper_read_a_century_later`, `paper_never_read`).
- Being cognitive is no longer a property of the transformation but a relation. Accepted as the theory's stance, stated in the glossary.
- The claimed infinite regress does not arise: one step of uptake suffices; the taker's own output need not be taken up.

## Consequences

- Self-uptake counts: the self is divided along time, so a later self is a taker (issue #9, `author_rereads_own_draft`). The framework needs no disequality.
- A system's transformation is derived by composition from chains of uptake, never from one component alone (`transformation_when_components_chain`, `transformation_composes_along_uptake`); a single component's transformation is not the system's.
- Stated and derived transformations share `transformation/3`; issue #11 records the tension this leaves.
