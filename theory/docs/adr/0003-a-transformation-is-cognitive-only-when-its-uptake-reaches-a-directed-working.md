# A transformation is cognitive only when its uptake reaches a working that a criterion directs

ADR 0001 defined a cognitive transformation by uptake alone: something takes the output up and transforms it, anywhere, under no criterion. That made "cognitive" coextensive with "a non-terminal link in a stated chain": a JPEG pipeline alone and the weather (`weather_is_not_cognitive`) came out as organised cognitive systems, and nothing in the Core could refuse them. The vault ties "cognitive" to a role in a system working under task criteria, goals or value gradients; 0001's arguments hit the vault's modal "can" and its presupposition of the larger system, not the criterion-relativity, and the fix over-corrected. The Core now defines the role the vault defines: a component serves as a mechanism in a system when the working of that directed system takes its output up (`mechanism_when_the_working_takes_up_its_output`), where the working takes a state up through a component that transforms it (`working_takes_up_through_a_component`) or through an evaluator judging under the system's criterion whose response returns into the system (`working_takes_up_through_a_returning_evaluator`). A transformation is cognitive when it makes its transformer such a mechanism (`cognitive_when_taken_up_by_the_working_of_its_system`), and a mechanism without a named system is one that serves in some system (`mechanism_when_it_serves_in_some_system`). This supersedes 0001's system-less mechanism as well as its definition of cognitive: 0001 split the vault's one role into a boundary-free `mechanism/1` and a boundary-relative `mechanism_in/2`, and once direction was required the boundary-free one had no answer to "mechanism of what". `cognitive_system`, `realises_intelligence` and `nested_in` inherit direction unchanged; the composition Claims stay criterion-free, so "transforms as a system" remains derivable (`turns/3`) without the cognitive name. A recurrent system stays structural, and a recurrent cognitive system is one that is also a cognitive system (`recurrent_cognitive_when_directed`); only that can revise. Decided in issue #16, at the rendering gate.

## Considered options

- Keep the uptake-only Claim under a new name and add the directed one on top. Rejected on name discipline: the undirected layer needs no name of its own (it is "transforms as a system", `turns/3`, via the composition Claims), and phenomena renamed onto it would test nothing about cognition.
- Require the chain of uptake to reach the component that takes the criterion up. Rejected for now: one step into a directed system is Horn-simple and already refuses every undirected case; the stricter form can be added if a phenomenon needs it.
- Keep 0001's system-less mechanism and require only the taker to be directed. Tried first in this issue and rejected: it left three senses of "mechanism" (in a system, of no system, and a cognitive transformation with two base cases) and could not answer whether a team member whose revision a silent editor reads is a mechanism. The vault has one sense, a role in a larger cognitive system; 0001's cases (the translator, the author read a century later, the last move before action) survive by drawing the boundary round transformer and taker (the exchange, the scholarship across the century, the game that includes the world), which the glossary already allows.
- Count an evaluator's uptake without a reply. Rejected: from the system's side a silent evaluator is an archive; ADR 0002 drew the same line for direction.
- Make recurrence require direction. Rejected: the vault defines recurrence as temporal re-entry, structural; the directed case gets its own Claim instead.

## Objections accepted with the decision

- The one-step rendering over-generates: a component of a directed system makes everything it takes up and transforms cognitive, whether or not it bears on the criterion (a radio's forecast that a team member takes up while the team works to a review criterion). The vault's "can bear on the larger system's ability … under relevant task criteria" would exclude it. Accepted for now; the stricter option above is the remedy if a phenomenon needs it.
- Under the evaluator route, the transformation the evaluator judges had no directed taker unless the author drew a system round the evaluator, so the team realised intelligence while its last member was no mechanism. Answered by `working_takes_up_through_a_returning_evaluator`: the returning evaluator is part of the working (`team_directed_by_an_editor` expects `is_mechanism(bob)`; `team_judged_without_reply` refuses it).
- Every mechanism verdict now needs the phenomenon author to draw the boundary, attribute the criterion and state its uptake. Accepted: the theory refuses structure, not facts, and the vault's own question is at what boundary a description best explains the behaviour. Whether the drawn criterion bears on the mechanism's output is not yet checked (the radio above); that is the next change, and it presupposes issue #17.

## Consequences

- A system that merely transforms as a system is not cognitive (`pipeline_alone`, `coupled_but_undirected`); a criterion that is only attributed still directs nothing (`pipeline_with_an_attributed_criterion`).
- Intelligence does not descend: a mechanism in an intelligent system need not be intelligent at its own boundary, and nesting requires the inner system directed at its own scale (`pipeline_as_mechanism_in_a_larger_system` refuses `nested`, `pipeline_with_a_comparator` expects intelligence).
- Mechanism-hood is boundary-relative and extends to whatever a directed system takes up and transforms, the environment included, when the phenomenon author draws the boundary so. The theory refuses cognition without direction; it does not judge the facts.
- The vault's "context-sensitive" qualifier, which 0001 dropped without recording it, stays out: it describes how a transformation depends on its input, orthogonal to direction, and the Core has no predicate for it. Tracked in issue #5 with the other unformalised passages.
- Phenomena that expect a cognitive observation must state a criterion and the component that takes it up; ten of slice 1's gained one, four flipped to refuse `cognitive_whole`, and every refuse states the criterion so that only the condition under test is absent.
